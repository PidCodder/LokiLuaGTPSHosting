Lua API
Every function your scripts can call, read from this server's engine. Not the upstream docs, which describe a different engine.

Callbacks
All optional, and each may be registered more than once. Handlers run in registration order. An error inside one is logged and swallowed, never fatal.

onPlayerSendRaw(function(player, packet) end) → boolean
live
Fires just before ANY variant packet is sent to a client, which is the wider version of onPlayerVariantCallback: that one is wired at two specific places, this one sits at the single point every variant passes through. packet is a 1-based array of the variant’s arguments, so packet[1] is always its name ("OnConsoleMessage", "OnDialogRequest", "OnFtueButtonDataSet" and so on) and the rest are whatever it carries. Return true to block the packet, anything else to let it through. Use it to log, filter, validate a custom variant before it goes out, or drop one entirely. To change a packet, block the original and send your own with player:sendVariant.

player
Who the packet is addressed to.
packet
The variant’s arguments, packet[1] being the name. Strings, numbers and floats come through as themselves; a 2 or 3 float vector arrives joined as "x,y" or "x,y,z".
-- log every dialog, and never let a half-built FTUE packet reach a client
onPlayerSendRaw(function(player, packet)
    local name = packet[1]

    if name == "OnDialogRequest" then
        sendLog(player:getName() .. " <- dialog, " .. #packet .. " args")
    end

    if name == "OnFtueButtonDataSet" and #packet < 5 then
        return true   -- blocked: not enough arguments to be valid
    end

    return false
end)
onPlayerSendRaw notes
live
Worth knowing before you use it. It only covers variant packets, which is everything named like OnSomething; the binary movement and tile stream does not pass through here. It costs nothing at all until a script registers a handler, and after that every outgoing variant runs your Lua, so keep the handler short. Packets your handler itself sends are passed straight through rather than fed back into it, so calling onConsoleMessage from inside is safe and will not recurse. If your handler throws, the error is logged and the packet is sent anyway, so a broken handler cannot silence the server. Blocking is powerful and sharp: dropping the wrong variant can leave a client stuck on a screen that never arrives, so match on packet[1] and let everything else through.

onPlayerCommandCallback(function(world, player, fullCommand) end) → boolean
live
Fires when a player types a /command. Lua gets first refusal, before the built-ins.

fullCommand
The command with no leading slash: "setdelay 1500".
return true
Handled. The built-in is skipped.
return false
Falls through to the next callback, then to the built-ins.
onPlayerCommandCallback(function(world, player, fullCommand)
    local cmd, args = fullCommand:match("^(%S+)%s*(.*)")
    if cmd == "mycmd" then
        if not player:hasRole(998) then return false end  -- hide from non-staff
        player:onConsoleMessage("args: " .. args)
        return true
    end
    return false
end)

onPlayerActionCallback(function(world, player, data) end) → boolean
live

sidebar click
Arrives as data.action = its buttonAction.
return true
Claimed. The built-in handling is skipped, which is how a script replaces a built-in screen.
return false
The engine carries on. Either way, every registered callback runs.

        world:sendPlayerMessage(player, "/sell")   -- runs the command
        return true
    end
    return false
end)

Fires about once a second. Cheap when unused. A handler that runs longer than its 1000ms budget is aborted rather than allowed to stack up.

end)

registerLuaCommand{ command, roleRequired, exactRole, description, callback }
live
Declares a command so it is listed and echoed like a built-in.

command
Name without the slash.
roleRequired
Who sees it in /help. Not a gate by itself, so keep your own hasRole check, or set exactRole. An admin can reassign it to a role in game, which does gate it.
exactRole
Only the role in roleRequired sees and runs it. Higher roles are refused. Enforced. The owner always passes.
description
Shown in listings.
callback
Optional f(player, args), tried before onPlayerCommandCallback.

    command = "card",
    roleRequired = 0,
    description = "Open your Credit Card"

    command = "vipshop",
    roleRequired = 1,
    exactRole = true,

getWorlds() → {World}
live
Worlds currently loaded in memory, as a 1-based array. NOT every world on the server -- only loaded ones. Key by world:getName(), not position.

local function findDrops(itemID)
    local hits = {}
    for _, w in ipairs(getWorlds()) do
        for _, d in ipairs(w:getDroppedItems()) do
            if d:getItemID() == itemID then
                hits[#hits + 1] = {
                    world = w:getName(),
                    x     = math.floor(d:getPosX() / 32),
                    y     = math.floor(d:getPosY() / 32),
                    count = d:getItemCount(),
                }
            end
        end
    end
    return hits
end

onPlayerCommandCallback(function(world, player, cmd)
    local id = cmd:match("^/finddrop%s+(%d+)$")
    if not id then return false end

    local hits = findDrops(tonumber(id))
    player:onConsoleMessage("`2" .. #hits .. "`` result(s) in loaded worlds")
    for _, h in ipairs(hits) do
        player:onConsoleMessage("`o" .. h.world .. "`` at " .. h.x .. "," .. h.y .. " x" .. h.count)
    end
    return true
end)

        left = left - 1

            p:onConsoleMessage("`2Giveaway`` starting soon!")
        end

http.post(url, headers, body) → boolean
live
Queues a POST in the background; the reply is discarded. http/https only, no redirects, no private addresses. 256 kbps, 20s, 16 at once.

url
Must start with http:// or https://.
headers
Optional table of header name to value, for example { ["Content-Type"] = "application/json" }.
body
Optional request body string (up to 256 KB).
http.post("https://discord.com/api/webhooks/ID/TOKEN",
    { ["Content-Type"] = "application/json" },
    '{"content":"Giveaway started!"}')
http.get(url, headers) → boolean
live
Sends an HTTP/HTTPS GET in the background. Returns whether it was queued, not the reply. Same rules as http.post.

http.get("https://example.com/ping")
http.request(options) → boolean
live
The only form that can read the reply. Add a callback and it gets res.ok, status, body and headers. Same limits as http.post.

url
Must start with http:// or https://.
method
Optional, defaults to "GET". Any verb, for example "PUT" or "DELETE".
headers
Optional table of header name to value.
body
Optional request body string (up to 256 KB).
callback
Optional function(res). Runs on the server tick after the reply arrives, never immediately.
res.ok
True when the request itself completed. A 404 or 500 is still ok, the code is in res.status.
res.status
HTTP status code, or 0 when the request never completed.
res.body
Response body, up to 512 KB. A larger reply fails outright rather than arriving cut in half, so you never parse half a document as if it were whole.
res.headers
Table of response header name to value. Names arrive lowercased by most servers. A header sent twice keeps the last value.
res.error
Only set when res.ok is false. Common values are "Timeout was reached", "response larger than 512 KB", a connection failure, and "server was too busy to deliver this response" if the server was overloaded when the reply came back.
http.request({
    url = "https://api.example.com/v1/search?query=love",
    method = "GET",
    headers = { ["Authorization"] = "Bearer TOKEN" },
    callback = function(res)
        if not res.ok then
            print("request failed: " .. tostring(res.error))
            return
        end
        if res.status ~= 200 then
            print("server said " .. res.status)
            return
        end
        print(res.headers["content-type"])
        print(res.body)
    end
})

addCookingRecipe{ result, ingredients, ... } → boolean
live
Declares a dish an oven can make. Returns false, and logs why, if the recipe cannot work.

name
Label shown in messages and returned by getCookingRecipes.
result
Item id the dish produces. Any item, it does not have to be food.
resultCount
How many to give. Default 1.
ingredients
Array of { id = itemID, seconds = n }. Order never matters, and an item may appear twice with different times. seconds is the oven time that scores 100 for that ingredient, measured at Low heat: Medium runs twice as fast and High three times, so one recipe fits all three settings.
perfectTime
Total cook time the dish wants, scored separately from the ingredients. Keep it at or below the slowest ingredient's seconds, or a flawless cook can never reach 100. Omit or 0 to score ingredients only.
minAccuracy
Below this the dish is ruined. At or above it the player always gets the dish and accuracy only changes the wording. Default 25.
ruinedResult
Item id handed back when a cook is ruined. Can be an ingredient, a consolation item, or the dish itself so the recipe can never be failed outright. Omit or 0 to give nothing.
ruinedResultCount
How many of ruinedResult. Default 1.
spices
Optional array of item ids. The set must match exactly to earn the bonus. Spices do not use an ingredient slot and are not timed.
spiceBonus
Added to accuracy when the spices match, subtracted when they do not. Default 10.
points
Your own number, stored and handed back by getCookingRecipes. The engine never reads it, so use it for a leaderboard.
addCookingRecipe{
    name = "Arroz con Pollo",
    result = 4604,
    perfectTime = 40,
    minAccuracy = 25,
    ruinedResult = 4564,
    points = 250,
    ingredients = {
        { id = 874,  seconds = 10 },
        { id = 4588, seconds = 20 },
        { id = 4564, seconds = 40 }
    },
    spices = { 4568, 4570 }
}

0 for the fruit count (trees only), 1 for the planted or provider cycle-start timestamp (trees and providers).
for _, t in ipairs(world:getTiles()) do
    local fruit = t:getTileData(0)
    if fruit and fruit > 0 then
        player:onConsoleMessage("Tree at " .. t:getPosX() .. "," .. t:getPosY() .. " has " .. fruit .. " fruit.")
    end

    -- index 1 is shared by trees and providers, so one check covers both
    local started = t:getTileData(1)
    if started then
        local left = started + getItem(t:getTileID()):getGrowTime() - os.time()
        if left <= 0 then
            player:onConsoleMessage("`2Ready`` at " .. t:getPosX() .. "," .. t:getPosY())
        end
    end
end
